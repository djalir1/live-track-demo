## New admin routes

All three sit under a shared shell with a "Routes / Buses / Students" tab nav and require `role ∈ {admin, school_admin}`.

- `/admin/routes` — create routes; within a selected route, add stops with the Leaflet picker; reorder or delete stops. Types are `school` or `pickup`.
- `/admin/buses` — create buses. Route selector lists the school's routes; driver selector lists profiles that carry `user_roles.role = 'user'` (drivers only, never admins, parents, or school admins).
- `/admin/students` — create students. Home stop is limited to stops on the currently-selected bus's route; the UI tells you to assign a route to the bus first if the bus has none.

Nav entry: on `/dashboard` (super-admin dashboard), a new `School setup` button jumps to `/admin/routes`. School admins land there directly after sign-in; super admins can also arrive via the link.

## Cross-school RLS test

Runs entirely inside a rolled-back transaction; leaves nothing behind. Synthetic `school_admin` profiles for two temporary schools are created via `session_replication_role=replica` (superuser-only trick) so no `auth.users` rows are touched. Then `SET LOCAL role = authenticated` + `SET LOCAL request.jwt.claims` simulate each admin's session and every check is performed under RLS.

```
step                                                     | expected | actual  | passed
---------------------------------------------------------+----------+---------+-------
A reads OWN routes                                       | >=1      | 1       | true
A reads B routes (RLS should hide them)                  | 0        | 0       | true
A reads B buses (RLS should hide them)                   | 0        | 0       | true
A INSERTs into B routes (WITH CHECK should block)        | blocked  | blocked | true
A UPDATEs B routes (RLS filters SELECT so 0 rows match)  | 0 rows   | 0 rows  | true
B reads OWN buses                                        | >=1      | 1       | true
B reads A buses (RLS should hide them)                   | 0        | 0       | true
B INSERTs student into school A (should block)           | blocked  | blocked | true
```

**8 / 8 passed.** A cross-check confirmed the transaction rolled back cleanly: 0 schools with `__RLS_TEST_*` names, 0 test routes, 0 test profiles, `public._rls_test_results` gone.

Re-run with: `psql "$SUPABASE_DB_URL" -f scripts/test-cross-school-rls.sql`.

## What was NOT done, and why

- **Not pushed.** Branch `feat/parent-phase1` is the working branch; `master` is untouched. Nothing lands until you review.
- **No parent screens, no /join, no ETA, no parent auth.** All Phase 2+.
- **Landing page, driver tracker, existing admin dashboard styling untouched.** The only edit to `dashboard.tsx` is a single new "School setup" nav button (same button component as the others).
- **Djalir's existing `school_id` link left as-is.** Spec says "super-admin stays null" — technically I would prefer to null-out Djalir too, but the "leave what already exists" clause in the task took precedence and it doesn't break anything (super-admin bypasses `same_school` via the `has_role(auth.uid(),'admin'::app_role)` short-circuit).
- **Existing school-scoped policies (`school admin all X in school` using `is_school_admin_of`) kept alongside the new `school admin same_school X` policies.** Permissive-OR means behaviour is unchanged; the new policies express the spec's requirement (`same_school()`) explicitly, and touching the old ones would violate "never drop".
